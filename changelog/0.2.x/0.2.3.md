# 0.2.3 — 2026-09-21

## Changed

- **`createApp()`** now declares `sessionMode: 'stateless'`, so an HTTP deployment with `MCP_SESSION_MODE` unset serves statelessly — a 2025-era `initialize` receives no `Mcp-Session-Id`; an explicitly set `MCP_SESSION_MODE` still overrides it, and stdio is unaffected. Matches the Docker image, which already ran stateless. (#14)
- **`@cyanheads/mcp-ts-core`** `^0.12.3` → `^0.13.6`: argument rejections carry `reason: invalid_arguments` with a schema-derived recovery hint (an unknown key names the keys the tool accepts); a case-folded undeclared key now aliases to its one matching declared key and a stringified array argument is repaired and re-parsed once before validation fails; error `content[]` text closes with `(reason <reason>)`.
- **Config** — a blank or unsubstituted `${…}` `DOCGEN_*` value now reads as unset and takes its default; a malformed value still fails startup. Server identity (version, description) resolves from the served package. `SIGTERM`/`SIGINT` exit the process explicitly (0 once shutdown settles, 1 past the 10s ceiling), and `/.well-known/mcp.json` publishes the resolved session mode under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]`.
- **Schema rendering** — the `zod` bump changes `docgen_export_spreadsheet`'s `sheets[].rows[]` and `docgen_fill_form`'s `fields` scalar-union schemas to advertise `type: [...]` instead of an equivalent `anyOf`; semantically identical.
- Bun engines floor `>=1.3.0` → `>=1.4.0`; skill tree moved `skills/` → `framework-skills/` (repo structure, not client-visible); README, issue forms, `.env.example`, and packaging metadata refreshed.

## Fixed

- **`docgen_render_pdf`** decodes each HTML character reference exactly once — `&amp;lt;` now renders as the literal `&lt;` instead of `<` — and numeric references (`&#169;`, `&#x2014;`) decode too, with unknown names left verbatim. `<script>`/`<style>`/`<head>` end tags carrying whitespace or attributes (`</script >`) are stripped instead of rendered as visible text, and a `--!>`-closed comment strips cleanly; applies to HTML sources and markdown text alike. (#15)

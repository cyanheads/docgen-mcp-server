# 0.2.0 — 2026-06-27

## Removed

- **`downloadUrl` emission** — `DocumentEnvelope.downloadUrl` is no longer populated on any code path. The `MCP_PUBLIC_URL`-derived `/documents/{documentId}` URL it advertised had no matching HTTP route, so a `GET` returned 404 ([#2](https://github.com/cyanheads/docgen-mcp-server/issues/2)). The field stays in the schema, reserved for a future HTTP download route, but is always absent; documents are delivered via the `docgen://document/{documentId}` resource URI and inline base64 (at or under `DOCGEN_INLINE_MAX_BYTES`). **Breaking:** consumers that read `downloadUrl` must switch to `resourceUri` / `inlineBase64`.

## Fixed

- **`template_render_failed` recovery hint** — the declared contract `recovery.hint` now reaches the wire. `ctx` is threaded through the private `resolveSourceToBlocks` / `renderTemplate` render helpers so the throw carries both `recovery.hint` and the existing `missingKey` in `data`, matching every other typed failure in the service ([#1](https://github.com/cyanheads/docgen-mcp-server/issues/1)).

## Security

- **`documentId` validation** — `docgen_get_document` and the `docgen://document/{documentId}` resource validate the id against `^doc_[A-Za-z0-9_-]{24}$` at the schema boundary, and `DocumentStore.get()` resolves a non-conforming id as not-found before any storage read. A malformed id (`bad:id`, `../../bad`) previously bypassed the `document_expired` contract and surfaced storage-key construction details — the internal `doc/meta/` namespace prefix — plus the raw validation reason ([#3](https://github.com/cyanheads/docgen-mcp-server/issues/3)).

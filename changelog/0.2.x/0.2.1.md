# 0.2.1 — 2026-06-28

## Fixed

- **`docgen_export_spreadsheet` worksheet names** — every sheet name is validated before the workbook is built, surfacing the declared `invalid_sheet_name` (`InvalidParams`) reason with a recovery hint instead of a generic ExcelJS throw or a silent over-31-character truncation. Enforced to match Excel: non-blank, 1–31 characters, no `* ? : \ / [ ]`, no leading or trailing apostrophe, and unique across the workbook (case-insensitive). The `name` schema description now spells out the constraints so they show in `tools/list` ([#4](https://github.com/cyanheads/docgen-mcp-server/issues/4)).
- **`docgen_fill_form` line-wrapped base64** — `decodeBase64Pdf` strips ASCII whitespace before validating, so base64 wrapped by CLIs, MIME encoders, or copy/paste decodes correctly; malformed base64 and non-PDF bytes are still rejected. The `sourcePdf.base64` description notes that whitespace and an optional `data:` prefix are tolerated ([#5](https://github.com/cyanheads/docgen-mcp-server/issues/5)).
- **`docgen_render_pdf` stray `data`** — `data` supplied without a `template` (e.g. `{ html, data }`) now throws the declared `invalid_source` reason instead of silently dropping `data`; `data` pairs only with `template` ([#6](https://github.com/cyanheads/docgen-mcp-server/issues/6)).
- **`docs/design.md` `downloadUrl` references** — the delivery-model section, flow table, and design notes now describe `downloadUrl` consistently as a reserved field not emitted in v1, with delivery via the resource URI and inline base64, matching the implementation ([#7](https://github.com/cyanheads/docgen-mcp-server/issues/7)).

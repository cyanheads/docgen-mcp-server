# 0.1.1 — 2026-06-25

First published release; the `v0.1.0` tag was an unpublished scaffold checkpoint. docgen renders the structured content an agent composes into the binary document a human downloads — no external API, a bundled `pdf-lib` / `exceljs` / `marked` rendering stack.

## Added

- **`docgen_render_pdf`** — render `{ html }`, `{ markdown }`, or `{ template, data }` to a PDF via the lightweight `pdf-lib` engine; `pageOptions` controls size, orientation, margins, header/footer, and page numbers. Sets a `degraded` enrichment flag when unsupported styling (CSS, images, scripts) is dropped.
- **`docgen_export_spreadsheet`** — render one or more named row sheets to an `.xlsx` workbook (`exceljs`), with an optional per-column type / width / number-format spec.
- **`docgen_fill_form`** — fill, and optionally flatten, the AcroForm fields of a supplied PDF; source as `{ base64 }` or an `{ url }` fetched behind an SSRF guard. Field names with no AcroForm counterpart return in `unmatchedFields[]` rather than failing the call.
- **`docgen_get_document`** — re-fetch a previously rendered document by `documentId` within its TTL.
- **`docgen://document/{documentId}`** resource — the stable-URI delivery surface: raw bytes as a blob (real mime type) plus a JSON metadata block.
- Shared **`DocumentEnvelope`** across every tool — `documentId`, resource URI, byte size, TTL, and inline base64 at or under `DOCGEN_INLINE_MAX_BYTES`. Bytes are delivered via the `docgen://document/{id}` resource URI (and inline base64 when small enough); `downloadUrl` is reserved for a future HTTP download route and is not emitted in v1.
- Tenant-scoped, TTL-bounded document store with a per-render byte ceiling and wall-clock timeout — configurable via `DOCGEN_DOCUMENT_TTL_SECONDS`, `DOCGEN_MAX_DOCUMENT_BYTES`, `DOCGEN_RENDER_TIMEOUT_MS`, `DOCGEN_INLINE_MAX_BYTES`, and `DOCGEN_PDF_ENGINE`.

## Changed

- Published under the **`@cyanheads/docgen-mcp-server`** npm scope — README install snippets, badges, and the Cursor / VS Code / `.claude-plugin` / `.codex-plugin` payloads reference the scoped name, and the `server.json` package identifiers match it with a `bun` runtime hint.
